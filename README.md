# SpaceOOP — моделирование Солнечной системы

Учебный проект на C# (.NET 8) по курсу «Технологии программирования на .NET»:
моделирование звёздной системы и работа с космическими телами через
консольное меню. Репозиторий содержит две практические работы:

- **lab1/SpaceOOP** — основы ООП: наследование, инкапсуляция,
  полиморфизм, интерфейсы
- **lab2/SpaceOOP2** — обобщения (generics): собственная обобщённая
  коллекция, ограничения обобщений, ко- и контравариантность

Весь код снабжён комментариями на русском языке, объясняющими ключевые
приёмы (иерархия классов, работа коллекции, вариативность и т.д.).

## Запуск

Требуется [.NET SDK 8.0](https://dotnet.microsoft.com/download/dotnet/8.0).

```bash
dotnet run --project lab1/SpaceOOP    # лабораторная 1
dotnet run --project lab2/SpaceOOP2   # лабораторная 2
```

Папки `bin/` и `obj/` не хранятся в репозитории (см. `.gitignore`) и
создаются автоматически при сборке.

## Лабораторная 1 — основы ООП

### Возможности

- Просмотр всех объектов системы (звёзды, планеты, спутники)
- Поиск объекта по названию
- Списки планет и спутников
- Расчёт расстояния между планетами
- Орбитальная информация: по объекту или по всем объектам сразу
- Управление космической миссией (запуск / завершение / статус)
- Астрономический каталог с поиском по названию

### Архитектура и ООП

#### Иерархия наследования

```
CelestialBody (abstract)
├── Star
├── Planet
└── Satellite
```

`CelestialBody` хранит общие характеристики (название, масса, радиус) и
объявляет абстрактный метод `ShowInfo()`, который каждый наследник
реализует по-своему.

#### Инкапсуляция

- Поле `mass` закрыто (`private`), доступ — через свойство `Mass`,
  которое проверяет корректность (`value <= 0` → `ArgumentException`).
- У большинства свойств только `get` — состояние задаётся через конструктор.
- `SpaceMission.Status` имеет `private set`: статус меняется только
  методами `Start()` и `Complete()`.

#### Полиморфизм

Все тела хранятся в `List<CelestialBody>`; при вызове `ShowInfo()`
выполняется реализация конкретного класса (`Star`, `Planet` или `Satellite`).
Метод `StarSystem.ShowAllObjects()` работает с базовым типом и не знает
о конкретных классах.

#### Интерфейс

`IOrbitalObject` (`OrbitalPeriod`, `OrbitRadius`, `ShowOrbitInfo()`)
реализуют `Planet` и `Satellite`. Метод `StarSystem.GetOrbits()` строит
орбиты всех объектов системы через этот интерфейс.

#### Взаимодействие классов

- `StarSystem` объединяет тела, ищет и фильтрует их (`GetPlanets`,
  `GetSatellites`, `GetOrbits`)
- `AstronomicalCatalog` ведёт отдельный каталог с поиском по имени
- `DistanceCalculator` считает расстояние между планетами
- `Orbit` описывает орбитальные характеристики объекта
- `SpaceMission` моделирует миссию между двумя объектами

Диаграмма классов: `SpaceOOP_ClassDiagram.drawio` (открывается в draw.io).

## Лабораторная 2 — обобщения (generics)

Вторая лабораторная развивает ту же предметную область: добавлена
собственная обобщённая коллекция и продемонстрирована вариативность
обобщённых интерфейсов. Вся демонстрация собрана в пункте меню
`10. Обобщённая коллекция и вариативность`.

### Что реализовано (требования работы)

| Требование | Реализация |
|---|---|
| Собственная обобщённая коллекция | `SpaceCollection<T>` на основе массива с авторасширением |
| Поддержка интерфейсов | `ICollection<T>`, `IReadOnlyList<T>`, `IEnumerable<T>` (с `IEnumerator<T>`), `ICloneable` |
| Ограничение обобщения | `where T : CelestialBody` на коллекции и методе `GetObjectsOfType<TResult>()` |
| Ковариантность (out) | собственный `ISpaceReader<out T>` + стандартный `IEnumerable<out T>` |
| Контравариантность (in) | собственный `ISpaceVisitor<in T>` + стандартные `IComparer<in T>` и `Action<in T>` |
| Внедрение в проект | `StarSystem` хранит тела в `SpaceCollection<CelestialBody>` вместо `List<CelestialBody>` |

### Как устроена SpaceCollection\<T\>

Коллекция хранит элементы во внутреннем массиве `T[]` с запасом ёмкости.
При нехватке места массив удваивается (как у стандартного `List<T>`).
`foreach` поддерживается через `IEnumerable<T>`: метод `GetEnumerator()`
написан с `yield return`, и компилятор сам генерирует `IEnumerator<T>`.
`Clone()` выполняет поверхностное копирование: копия коллекции независима
по составу (Add/Remove одной не влияют на другую), но ссылается на те же
объекты тел.

### Вариативность — в двух словах

- **Ковариантность (`out T`)** — «от частного к общему»:
  `ISpaceReader<Planet>` можно присвоить переменной
  `ISpaceReader<CelestialBody>`, потому что T только возвращается.
- **Контравариантность (`in T`)** — «от общего к частному»:
  `ISpaceVisitor<CelestialBody>` можно присвоить переменной
  `ISpaceVisitor<Planet>`, потому что T только принимается параметром.

Подробные пояснения — в комментариях в коде (`Collections/` и
демо-методы `ShowCovarianceDemo` / `ShowContravarianceDemo` /
`ShowComparerDemo` в `Program.cs`).
